Files and projects

          
A project is the set of jBC files you’re working on. Use + to add a
            file, click a tab to edit it, and use Main to pick the file where
            execution starts. Try Status lookup (3 files) in the
            Example menu to see how multiple files fit together.

        

        

          
Link as routine

          
Check this on a separate file that declares a SUBROUTINE or
            FUNCTION your program uses. In Status lookup, caller.b
            is the main file, and linking get.status.b makes
            CALL GET.STATUS(...) work. Leave I_STATUS unchecked
            because $INSERT I_STATUS already brings it into the files that use it.

        

        

          
Run and stop

          
Run compiles the project and executes it in your browser if
            compilation succeeds. Click a diagnostic’s file and line to jump to it. For a
            program that uses INPUT, fill in Standard input
            before running. Stop cancels a build or stops a running program.

        

        

          
GitHub sign-in and limits

          
The hosted playground uses GitHub sign-in to verify pilot access, keep cloud saves
            private to your account, and share build capacity fairly. Each invited account can
            have one build in progress and start up to six builds in a rolling minute. Local
            mode can run programs without sign-in and uses browser drafts.

        

        

          
Program limits

          
A build can include up to 32 files, 64 KiB of source per file, and 256 KiB of source
            total. A browser run has five seconds, 64 MiB of WebAssembly memory, and 64 KiB of
            combined output.

        

        

          
Save and load a cloud project

          
    
            
  1. Sign in on the hosted playground. To save, enter a name in Cloud project
              and click Save. This stores your source files, main file, and linked routines.
    2. 
            
  2. To open a save, click Projects and select its name, or type the name directly.
              The selection fills the name field. Click Load and confirm to replace the
              current draft.
    3. 
            
  3. To update a saved project, load it, make your edits, and save under the same name. If another
              tab saved a newer version, keep a copy of your edits before loading that version.
    4. 
          

          
The browser also keeps a local draft as you edit. Use Save when you
            want to open the project from another browser or device with the same GitHub account.
            To download a cloud save as a file, load it and click Export.

        

        

          
Save, load, and back up projects

          
    
            
  1. Enter a Project name and click Save to keep
              the current project in this browser.
    2. 
            
  2. Choose a name from Projects or type it directly. Click
              Load and confirm to open that save.
    3. 
            
  3. After you save or load a named project, changes autosave to that name.
              To save a copy under a different name, enter it and click Save.
    4. 
          

          
The browser also keeps a local draft as you edit. To back up a project or
            move it to another browser, click Export to download a file.
            Use Import to open a project file, including an export from
            the cloud playground. Clearing this site's data removes browser saves.
